# Интеграционный тест-план — Movies Picker

**Авторы:** Коба Алексей Юрьевич, Вдовина Светлана Алексеевна, Месропян Артём Вячеславович

---

## 1. Цель тестирования

Проверить корректное взаимодействие модулей приложения:

- модуль аутентификации (auth)
- модуль профиля пользователя (profile)
- модуль фильмов (movies)
- модуль «Смотреть позже» (watchlist)
- модуль рейтингов (ratings)
- модуль обзоров с интеграцией YouTube (reviews)

## 2. Область тестирования

### Тестируемые модули и их взаимодействие

```
[HTTP Client] → [REST API] → [Service Layer] → [Repository] → [PostgreSQL]
                                             ↓
                                     [Mock YouTube API]
                                     [Mock Kinopoisk API]
```

### Изоляция внешних сервисов

Для изоляции от реальных внешних API используется **mock-сервер** (`test/mock-server/`), который:

- Отвечает на запросы Kinopoisk API по адресу `http://mock-server:9090/api/v2.2`
- Отвечает на запросы YouTube API по адресу `http://mock-server:9090/youtube/v3`
- Возвращает предсказуемые фиксированные данные
- Работает в Docker-сети вместе с API-сервером

Переключение: API-сервер читает `KINOPOISK_BASE_URL` и `YOUTUBE_BASE_URL` из переменных окружения.

## 4. Инструменты

| Инструмент       | Назначение                              |
| ---------------- | --------------------------------------- |
| Go test          | Запуск тестов, отчётность               |
| testify          | Assertions (assert, require)            |

## 5. Тестовое окружение

- PostgreSQL 13 (в Docker)
- Mock-сервер на порту 9090 (в Docker)
- API-сервер на порту 8080 (в Docker)
- API использует `KINOPOISK_BASE_URL=http://mock-server:9090/api/v2.2`
- API использует `YOUTUBE_BASE_URL=http://mock-server:9090/youtube/v3`
